# Stox 设计说明

## 1. 目标

做一个“看一眼就走”的行情工具：

- **一键开关**。左键单击菜单栏图标弹出面板，再单击、点别处或按 Esc 立即收起；不占 Dock。
- **一键隐藏**。右键单击菜单栏图标，在“显示行情”和“只显示图标”之间切换。
- **不打开面板也能看**。关心的一两只股票直接显示在菜单栏上，带涨跌颜色；不想要颜色时可以全部用系统默认色。
- **轻**。原生 App，压缩包约 3.6MB，打开面板时内存占用约 30MB（活动监视器口径，CI 实测），休市时每分钟才请求一次。
- **免配置**。不需要账号和 API Key，装好就有 A 股、港股、美股主要指数。

## 2. 技术选型

| 方案 | 结论 |
|---|---|
| Swift + AppKit/SwiftUI（采用） | 原生菜单栏 API 完整，体积小、内存低、启动快，外观和系统一致 |
| Electron / Tauri | 为一个菜单栏小工具带上浏览器内核，内存和体积都不划算 |
| Python + rumps | 只能做下拉菜单，界面受限，分发时要打包解释器 |

菜单栏部分选择 **NSStatusItem + 自己的玻璃面板** 而不是 SwiftUI 的 `MenuBarExtra`：

- `MenuBarExtra` 的标签只能单色渲染，做不了红涨绿跌的菜单栏行情。
- `MenuBarExtra` 没有打开 / 关闭的编程接口，全局快捷键无法控制它。
- `MenuBarExtra` 不区分左右键，做不了“左键开面板、右键切换隐藏”。

面板内容用 SwiftUI 编写，由 `NSHostingView` 承载，SwiftUI 量出的尺寸通过 PreferenceKey 传回来，窗口顶边不动、按内容调整高度。量的是内容本来的高度（`fixedSize`），不让 SwiftUI 为了凑窗口把内容压扁，否则量出来的比实际矮，放不下也发现不了。内容变高时 NSHostingView 常常先自己把窗口撑高，比报尺寸的回调还早，所以窗口尺寸一变也按实际高度（`fittingSize`）再调整一次。屏幕放不下时先把自选列表压矮（最少两行），还放不下就把列表上方的卡片（更新提示、小技巧、持仓合计）放进能滚动的区域（最少 120 点高），面板底下的按钮总在屏幕里。CI 的屏幕只有 768 点高，每次都检查最高的几种面板（使用提示加更新提示、展开了分布和盈亏记录的持仓）放不放得下；更新内容是从 GitHub 取的，到得晚，所以检查用的是打开面板 6 秒后再报的尺寸。

### 玻璃面板

0.1.0 用的是 `NSPopover`。它自带的箭头和不透明底色做不出透出桌面的玻璃效果，0.2.0 换成了无边框的 `NSPanel`（`PanelWindow`），外观和 [Proxi](https://github.com/whrss9527/proxi) 保持一致：

- 底层是 `NSVisualEffectView`（`.hudWindow` 材质，`behindWindow` 混合），透出后面的桌面和窗口；上面一层由浅到透明的高光和一圈细边。
- 面板里的标题、搜索框、列表、更新条都是半透明材质的卡片（`glassCard`）。用 Xcode 26 编译、运行在 macOS 26 上时，卡片换成系统的 Liquid Glass（`glassEffect`）；其他情况回退到系统材质，所以 macOS 13 也能用。
- 面板是 `.nonactivatingPanel`：能接收键盘输入（搜索框、Esc、⌘R），但不激活 Stox，打开面板不会让正在用的 App 失去焦点，关掉后也不用“把焦点还回去”。
- 因为不激活程序，主菜单收不到 ⌘C、⌘V 这些编辑快捷键，面板自己把它们转给文本框。

### 一键开关与一键隐藏

- 菜单栏按钮在按下鼠标时响应（和系统菜单一样）。左键打开或关闭面板；右键或 Control + 单击切换“只显示图标”，不再弹出菜单，设置和退出放在面板底部。
- 面板失去焦点（点其他 App、桌面或别的菜单栏图标）时关闭。点菜单栏图标本身也会先让面板失去焦点，所以记下自动关闭的时间，0.3 秒内的那次点击不再把面板打开，避免“关不掉”。
- 和系统菜单一样即点即开，没有弹出动画，再点一下就收起。
- Esc 分层处理：有搜索内容先清空，在二级页面先返回，最后才关闭面板。
- 每次关闭都回到干净的列表页，下次打开直接看到行情。
- 自选跨了两个以上市场时，列表上方有一排筛选：全部、A股、港股、美股（只列出有的市场），有的有持仓、有的没有时再加“持仓”。选中的记在本机；筛选着的时候也能拖动排序，只在看得见的几只原来占的那些位置之间换，看不见的原地不动（`Watchlist.moving`）；键盘上下选择只在看得见的几只里走。
- 自选可以分组：每只最多属于一个分组（`WatchItem.group`，最多 10 个字），右键菜单里放进已有的分组或移出，编辑页里填新的组名；分组编辑页（面板里的一页，不用弹出框，免得面板失去焦点就关掉）可以改组名、一次勾选多只，也可以解散，放进来的会从原来的分组移出。筛选栏在市场和持仓后面按第一次出现的顺序列出各个分组，整个自选都在同一个分组里时不列；分组多了放不下时筛选栏可以左右滚动，右键分组可以解散。正在看某个分组时新添加的证券自动放进这个分组，免得加完看不到。列表上方的持仓合计也跟着筛选走，筛选着的时候第一列的表头写着筛的是什么；菜单栏的今日盈亏始终算全部持仓。分组存在自选列表里，跟着 iCloud 同步；设置里记的是 `group:组名`，分组没了就回到“全部”。
- 每一行右边的色块默认显示涨跌幅，点一下依次换成涨跌额、总市值（指数没有市值，显示 --），所有行一起换，也可以在底部的排序菜单里选。
- 迷你分时（默认打开）：标准列表的每一行在现价左边画一条当天的分时，虚线是昨收。分时按时间平均分成 48 段、每段取最后一个价格（`Sparkline`），横轴和分时图一样只有交易时段；两次取数之间，末端那一段用实时行情更新。面板打开、列表显示着的时候才取：一只一只地取，中间隔 0.15 秒，交易时段内两分钟一轮、休市时十分钟一轮，展开某只时取的分时也顺便更新它。展开的那只（下面有大的分时图）、紧凑列表和场外基金不画，紧凑列表时也不取。
- 紧凑列表（默认关闭）：每只一行 30 点高，市场、名称、代码、状态标签、现价和色块排在一起，持仓盈亏和盘前盘后价在展开后看；列表高度、屏幕放不下时的最小高度都按行高算。
- 列表可以按涨幅或跌幅排序（没有行情的排在最后），这时不能拖动；价格变动时价格背后闪一下，颜色跟着涨跌颜色的设置走，可以在设置里关掉。
- 第一次打开时列表上方有几条使用提示，更新到新版本后提示一次“已更新到 x.y.z”，都可以关掉。
- 每一行给读屏软件的内容是名称、代码、现价、涨跌幅和持仓盈亏。
- 键盘操作在面板窗口的 `sendEvent` 里处理：不带修饰键的方向键和回车先交给面板，处理了就不再交给搜索框。搜索时 ↑ ↓ 在还没添加的搜索结果里移动，默认高亮的就是回车会添加的第一条；没在搜索时 ↑ ↓ 在自选里移动，回车展开，展开后 ← → 切换走势图的周期。输入法正在组字时一律不拦，方向键和回车留给输入法选字。
- 全局快捷键默认 ⌃⌥S，可以在设置里录一个新的组合（至少带一个修饰键），使用 Carbon `RegisterEventHotKey`，不需要申请“辅助功能”权限。组合已被其他程序占用时，设置里会提示换一个。
- App 设置了 `LSUIElement`，只在菜单栏出现，不占 Dock 和 ⌘Tab。设置窗口打开期间临时切成普通 App，能用 ⌘Tab 切到它，关闭后回到只有菜单栏图标。

### 钉住成悬浮窗

面板右上角的图钉把面板变成悬浮窗：点别处不再关闭，可以拖着玻璃背景移动到任何位置，层级从菜单级别降到普通的浮动窗口，不挡系统菜单。位置记在本机，下次打开放回原处，那块屏幕不在了就放到主屏幕里。按 Esc、点菜单栏图标或者快捷键照样关闭；取消钉住后回到菜单栏图标下面。

### 设置窗口

设置从面板里的二级页面搬到了独立窗口：透明标题栏、全尺寸内容、左侧导航，整个窗口是毛玻璃。分四页：通用（刷新、提醒、快捷键、登录时启动）、显示（菜单栏、涨跌颜色，以及行情面板里的紧凑列表、价格闪动、均线和美股盘前盘后价）、iCloud 同步、关于与更新。单只证券的提醒和简称仍在面板里编辑，改完直接回到列表。

## 3. 架构

```
┌──────────────────────── Stox（macOS App）────────────────────────┐
│ AppDelegate        生命周期、睡眠唤醒、全局快捷键、通知             │
│ StatusItemController  菜单栏按钮（彩色行情 / 图标）、左键面板、右键隐藏 │
│ PanelWindow / PanelView  玻璃面板：列表、搜索、详情、单股编辑、更新条 │
│ SettingsWindowController  设置窗口（SwiftUI，四页）                  │
│ QuoteStore         自选列表 + 轮询 + 提醒（@MainActor ObservableObject）│
│ SettingsStore      偏好设置（UserDefaults），分同步和只在本机两类     │
│ SyncManager / CloudFile  iCloud 云盘同步                            │
│ Updater / UpdateInstaller  检查、下载、校验、替换、重新启动          │
└───────────────────────────────┬──────────────────────────────────┘
                                │ 只依赖纯 Swift 类型
┌────────────────────── StoxCore（Linux 也能编译测试）───────────────┐
│ Symbol / SymbolInput   统一代码格式与用户输入解析                     │
│ QuoteProvider          行情源协议；TencentProvider 为默认实现          │
│ TencentQuoteParser / TencentSearchParser  接口解析                   │
│ MarketClock / RefreshPolicy  交易时段、节假日识别、刷新节奏           │
│ AlertEngine            价格提醒判定（每条件每日一次）                 │
│ QuoteFormatter / MenuBarTicker / Watchlist  显示与持久化              │
│ SyncDocument / SyncRules  同步文件格式、合并与“该拉还是该推”的判断     │
│ UpdateCheck / InstallLocation  发布信息解析、版本比较、装到哪里        │
└──────────────────────────────────────────────────────────────────┘
```

界面无关的逻辑全部放在 StoxCore，用真实接口返回做单元测试；App 层只负责展示和系统集成。换行情源只需要实现 `QuoteProvider` 协议。

## 4. 行情数据源

| 数据源 | 覆盖 | 问题 |
|---|---|---|
| 腾讯 `qt.gtimg.cn`（采用） | 沪深北、港股、美股、指数、ETF、场外基金、国际期货和外汇 | 港股延时约 15 分钟 |
| 新浪 `hq.sinajs.cn`（备用，环球股指只用它） | 同样全面，还有环球股指 | 需要伪造 Referer，港美股代码格式各不相同 |
| 东方财富 `push2` | JSON 格式 | 美股要事先知道交易所编号 |
| Yahoo Finance | 美股好 | 需要 cookie/crumb，A 股数据差，国内访问不稳定 |

腾讯接口的优点：

- 一个请求取回任意市场的多只证券：`https://qt.gtimg.cn/utf8/q=sh600519,hk00700,usAAPL,us.IXIC`。
- 有 UTF-8 版本（路径里的 `/utf8/`），不用处理 GBK。万一退回 GBK，也有 GB18030 解码兜底。
- 搜索接口 `smartbox.gtimg.cn` 支持代码、中文名、拼音首字母，结果自带市场前缀。

返回的字段位置在 `TencentQuoteParser` 的注释里有完整对照表。单位差异在解析时统一：A 股成交量由“手”换算成“股”，成交额由“万元”换算成“元”，市值由“亿”换算成“元”。科创板例外，它的成交量、内外盘本来就是股（第 61 位的类别是 `GP-A-KCB`，成交额除以成交量正好是价格），不再乘 100；K 线和分时接口里科创板的量也是股。价格小数位沿用交易所报价精度，例如 ETF 3 位、港股 3 位、指数 2 位。

场外基金用同一个行情接口，代码前缀是 `jj`（`jj161725`），返回只有 10 个字段：`161725~招商中证白酒指数A~0.0000~0.0000~~0.5166~2.2327~-0.8065~2026-09-28~`，第 5 位是单位净值、第 6 位累计净值、第 7 位日涨跌幅（%）、第 8 位净值日期，第 2、3 位是 0（没有盘中估值；天天基金的估值接口 `fundgz.1234567.com.cn` 从境外访问是 404 页面，没法验证，没用）。解析时现价是单位净值，昨收按涨跌幅倒推，时间是净值日期那天 15:00，价格保留 4 位小数；有净值就算“有成交”，提醒、持仓和今日盈亏都照常算，今日盈亏用的是最新一天的净值涨跌，当天的净值要晚上才出。基金的时间比盘中行情晚一天，判断 A 股交易时段时不算它们，只有基金时按交易时间表算（节假日认不出来）；收盘小结、盈亏记录用的交易日有盘中行情时也不算它们，只有基金时看净值日期，所以要等晚上净值出来才记、才发。搜索接口本来就会返回 `jj` 的结果，`161725.OF` 这种写法也认。新浪备用行情里没有基金，不去请求。
- 注意：旧版本不认识 `jj`，读自选时会跳过这一只；几台 Mac 用 iCloud 同步时，旧版本写回去的自选里就没有基金了。

期货外汇也用同一个行情接口，和股票放在同一个请求里。国际期货和贵金属现货的代码是 `hf_` 加品种（`hf_XAU` 伦敦金、`hf_GC` 纽约黄金、`hf_CL` 纽约原油、`hf_OIL` 布伦特原油），返回逗号分隔的 14 个字段：`4141.36,0.64,4141.36,4141.71,4144.88,4113.30,14:00:00,4114.93,4117.01,0,0,0,2026-09-29,伦敦金（现货黄金）`，依次是现价、涨跌幅、买价、卖价、最高、最低、时间、昨收（期货是昨天的结算价）、今开、三个没用的数、日期和名称，时间是北京时间，价格两位小数。外汇的代码是 `wh` 加两种货币（`whUSDCNY`，美元指数是 `whUSDX`），`~` 分隔的 22 个字段：第 3 位现价、第 5 位时间（北京时间）、第 6 位昨收、第 7 到 9 位开高低、第 10、11 位买价卖价、第 19、20 位 52 周最高最低，价格四位小数（美元日元这种去掉末尾的 0 是两位）。2026 年 9 月实测能取到的品种写在 `GlobalCatalog` 里：14 种国际期货和贵金属、20 个外汇（`whUSDCNH`、`whJPYCNY` 没有，`whEURJPY`、`whDINIW` 停在 8 月）。腾讯的搜索接口搜不到这些，搜索时先在这张表里按中文名、英文、代码和拼音首字母找，排在股票前面（回车添加第一条，所以字母至少两个才算完全相同、三个才看开头，两个字母的拼音首字母不放）。它们和下面的环球股指算一个“环球”市场（`MarketRegion.global`，列表上方的筛选和代码里原来都叫“期货外汇”）：工作日几乎全天交易，按纽约时间周日 18:00 到周五 17:00 算交易中；节日休市认不出来，按行情停了 3 小时以上当休市。腾讯的分时、五日、K 线接口都不认它们（`code param error`）。国际期货的分时用新浪的 `stock2.finance.sina.com.cn/futures/api/jsonp.php/var%20t1hf_GC=/GlobalFuturesService.getGlobalFuturesMinLine?symbol=GC`（JSONP，第一条多了交易日、昨结算和交易所，之后每条是“时刻、价格、成交量、持仓量、均价、日期时间”，北京时间）：一个交易日跨过半夜，开盘的时刻也各不一样（纽约的期货和伦敦金北京时间 6 点、冬令时 7 点，布伦特原油 8 点，恒指期货前一天 17:15 的夜盘算这一天的），所以分时点的 minute 是离第一条多少分钟，`IntradaySeries.start` 记下第一条的时间，横轴从它画 24 小时，下面标开盘、12 小时后和 24 小时后的北京时间，读数里的时刻也从它换算；迷你分时同样按离开盘多少分钟分段。新浪的均价是按价格算的、纽约的期货成交量是 0，这两样不画。外汇的分时接口 `NewForexService.getMinKline` 从境外取一整天要十几秒，美元指数（`DINIW`）没有数据，暂时不接，外汇展开后只有开高低收、买卖价和 52 周最高最低，列表里也不画迷你分时；期货写振幅。五日和 K 线都没有。价格没有统一的货币（外汇是另一种货币的汇率，期货是每盎司、每桶多少美元），不能填持仓，价格提醒照常。新浪的 `hf_` 行情字段位置和腾讯一样，腾讯取不到时照样用；新浪的外汇是另一套代码（`fx_susdcny`）和字段，不去请求。旧版本同样会跳过这些代码。

环球股指（日经225、富时100、德国DAX 这些）在腾讯的行情接口里只试出日经（`gzN225`，只有名称、时间、现价和涨跌，没有开高低），用的是新浪的 `znb_` 代码，市场前缀是 `zn`（`znb_NKY`，`Symbol.rawValue` 就是新浪的代码，和 `hf_` 一样多写几个字），算在“环球”里、按指数处理（价格两位小数，不能填持仓）。返回逗号分隔的 13 个字段：`日经225,68956.5000,2202.78,3.30,2:12 AM,1759126320,2026-10-01,14:30:01,67106.5200,66753.7200,68995.3000,67081.6600,0`，依次是名称、现价、涨跌、涨跌幅、两个没用的旧时间、日期和时间（北京时间，东京 15:30 收盘就是 14:30）、今开、昨收、最高、最低和成交量（多数是 0）。2026 年 10 月实测 13 个字段齐全、日期是当天的写在 `GlobalCatalog` 里（日经、富时100、DAX、CAC40、斯托克50、韩国综合、印度SENSEX、台湾加权、海峡时报、巴西IBOVESPA）；多伦多（`znb_SPTSX`）、瑞士、台北指数只有前 6 个字段，数据停在一年前，不认；澳洲标普200（`znb_AS51`）字段齐全但停在前一天，不放进品种表；`int_` 系列只有现价和涨跌，`b_` 系列和 `znb_` 一样。名称用品种表里的，新浪的有的过时了（“德国DAX30”）。腾讯的数据源取行情时把它们交给新浪，和腾讯的请求同时发出：新浪取不到时不耽误别的行情，只有环球股指时照常报错，交给备用数据源（也是新浪）再试。没有分时、五日和 K 线；展开后是今开、最高、最低、昨收、涨跌、涨跌幅和振幅。旧版本不认识 `zn`，同样会跳过。

资金流向来自腾讯的 `proxy.finance.qq.com/cgi/cgi-bin/fundflow/hsfundtab?code=sh600519&type=todayFundFlow,todayFundTrend,fiveDayFundFlow`（type 可以一次要几样）：`todayFundFlow` 是当天的合计（主力流入、流出、净流入，超大单、大单、中单、小单各自的净流入，主力净流入在全部 A 股里的排名和一句小结），`todayFundTrend` 是每分钟累计的主力净流入和价格，`fiveDayFundFlow` 是之前 5 个交易日每天的主力净流入。数字都是字符串，单位是元。主力是超大单加大单（一笔成交额不少于 20 万元或者不少于 6 万股）。只有 A 股个股和 ETF 有，ETF 没有排名；开盘前当天的合计是 null，这时显示“暂无资金流向”。展开后切到“资金”才请求，交易时段内每分钟刷新一次。老的 `qt.gtimg.cn/q=ff_sh600519` 已经不返回数据了。

A 股个股（含 ETF，不含指数）的行情里还有买卖五档：第 9 到 18 位是买一到买五的“价、量”，第 19 到 28 位是卖一到卖五，挂单量都是手（科创板也是）；第 7、8 位是外盘、内盘。价格是 0 的档没有挂单：开盘前、停牌时全是 0，集合竞价时第一档是虚拟成交价和匹配量、第二档只有未匹配量没有价格，涨停时卖盘是空的。委比按五档自己算（委买减委卖，除以两者之和），和接口第 74 位给的一致。腾讯里港股的“买一”“卖一”只是现价、没有量，美股只有第一档，都不显示五档。新浪的 A 股同样有五档（第 10 到 29 位，每档先量后价，量是股），没有内外盘。

展开详情时的分时图来自腾讯的分时接口：A 股、港股是 `web.ifzq.gtimg.cn/appstock/app/minute/query?code=sh600519`，美股（含指数）是同一个域名下的 `UsMinute/query?code=usAAPL`。每分钟一条“时刻 价格 累计成交量”，时刻是交易所当地时间。只在展开时请求，交易时段内每分钟刷新一次，收起后停止。分时图的横轴只包含连续交易时段：A 股 240 分钟、港股 330 分钟、美股 390 分钟，午休不占位置，港股收市竞价放在最右边。

分时的每条都带着累计成交量，相邻两条相减就是每分钟的成交量，画在分时图最下面四分之一，按这一分钟比上一分钟涨了还是跌了上色；开盘那一分钟带着集合竞价的量，常常比别的分钟大好几倍，最大的一根超过第二大的 3 倍时按第二大的 1.2 倍来比，它顶到头，别的柱子不会被压得看不见。鼠标指着时读数里有那一分钟的量。个股的分时每条还带着累计成交额，均价线就是成交额除以成交量。A 股的成交量是手、港股是股，看最后一条算出来的比值是价格的一百倍左右还是差不多，就知道要不要乘 100，不用按市场写死。美股的分时只有累计成交量，按每分钟新增的成交量给那一分钟的价格加权，是个近似。指数的成交量、成交额是成分股加起来的，不画均价线。算出来明显不在当天价格范围里的（接口数据有问题）丢掉。分时图右上角写着最新的均价，鼠标指着时读数里有那一分钟的均价。图下面一行标出开盘、午休（上午收盘和下午开盘在同一个位置，写成“11:30/13:00”；美股没有午休，标中间的 12:45）和收盘的时刻；四个角的小字是图上画出来的最高、最低值（价格、均价和昨收里的）和它们相对昨收的涨跌幅。五日图下面标每天的日期，K 线下面标头、中、尾三根的日期。五日图的每一天用同样的办法各算各的，均价线天与天之间断开。

五日图来自 `appstock/app/day/query?code=sh600519`（美股是 `dayus/query?code=usAAPL.OQ`，同样要带交易所后缀），返回最近五个交易日各自的分时和昨收，最近的一天在最前面。画的时候从早到晚排，每天占一样宽，竖线分开各天，虚线是第一天的昨收；鼠标指着时显示那一天的日期、时刻、价格和那一天的涨跌幅。最下面四分之一是成交量柱：五天一千多分钟挤在三百来个点里，按每两个点宽一根把那几分钟的量加起来（`MultiDaySeries.volumeBuckets`，收盘那一分钟算在自己那一天）；每天开盘那一根带着集合竞价的量，按不为 0 的柱子里排在 95% 的那根的 1.5 倍顶满（`volumeCap`），用淡淡的中性色，不分涨跌。

K 线来自腾讯的前复权 K 线接口，三地各一个地址：A 股 `appstock/app/fqkline/get?param=sh600519,day,,,60,qfq`，港股 `hkfqkline/get`，美股 `usfqkline/get`。每条是“日期 开 收 高 低 成交量”，后面可能跟着分红、回购这类附加信息；前复权数据的键是 `qfqday`、`qfqweek`、`qfqmonth`，指数是 `day`、`week`、`month`。美股个股要带交易所后缀（`usAAPL.OQ`、`usBRK.B.N`），不带时只返回很久以前的一根和今天的一根，所以解析行情时顺便记下第 2 个字段里的交易所代码，查 K 线时用它。图上显示最后 60 根，向接口要 80 根：多出来的 20 根只用来算 5、10、20 根的收盘价均线和第一根的涨跌幅，所以均线从图的最左边就有。均线画在 K 线上面，图的上方留一行写均线的值，鼠标指着时是那一根的，否则是最后一根的；纵轴同时容下 K 线和均线。每条 K 线的第 6 个字段是成交量（A 股是手，港股、美股是股），按图上最大的一根的比例画在最下面四分之一，颜色和 K 线一样但淡很多，K 线压在上面；行情里的成交量单位不一样（A 股是股），所以用实时行情更新最后一根时成交量沿用接口给的，新补的一根等下一次请求再画。K 线只在切到对应周期时请求，交易时段内每分钟刷新，休市时半小时一次；两次请求之间最后一根由实时行情更新，新的一天、一周、一月补上一根，所以 K 线和列表里的价格总是一致。

美股个股的盘前盘后价不在实时行情里（美股行情的第 67 位是当天的成交均价，即成交额除以成交量，不是盘前盘后价），而在美股 K 线和分时接口返回的 `pandata` 里：`{"last":"338.43","pct":"-0.77","netchange":"-2.64","time":"2026-09-28 16:03:14","tag":"after",…}`。`last` 是最新成交价，`tag` 盘后是 `after`、盘前按 `pre` 认，认不出时按美东时间分上午下午，`time` 是美东时间，常规交易时段里 `last` 是 -1。美股不在常规交易时，App 用只要一根日 K 的地址（`usfqkline/get?param=usAAPL.OQ,day,,,1,qfq`，返回很小）逐只去取：盘前盘后至少隔 15 秒一次（美股个股多时按每只 2 秒放慢），休市时半小时一次，常规交易时段里、设置里关掉时不取也不显示。`pct`、`netchange` 相对的是前一个交易日的收盘，盘后时把当天常规交易的涨跌也算进去了，所以涨跌按行情里的现价自己算：盘后时现价就是当天的收盘价，盘前时是上一个交易日的收盘价。盘后成交要和行情是同一天，盘前成交要晚于行情那天，对不上（接口还没切到最新的时段）时不显示。

腾讯的行情接口取不到（请求出错，或者一只都没返回）时，实时行情改用新浪财经 `hq.sinajs.cn/list=sh600519,hk00700,gb_aapl`。新浪必须带 `Referer: https://finance.sina.com.cn/`，否则返回 403；返回 GB18030 编码、逗号分隔，三地字段位置不同，对照表在 `SinaQuoteParser` 的注释里。美股代码是 `gb_` 加小写代码，指数去掉点（`gb_ixic`），分级股的点换成 `$`（`gb_brk$b`）。A 股价格一律三位小数，按开、昨收、现价、高、低里实际用到的位数决定显示两位还是三位。主数据源失败后两分钟内直接用备用的，免得每次刷新都先等超时，之后再试腾讯，恢复了就切回去。名称只从腾讯记，两家叫法有细微差别，来回改会让 iCloud 同步个不停。搜索、分时、K 线、盘前盘后价和汇率只用腾讯，切到新浪时这些暂时取不到，面板底部会说明。

分时接口一次只能查一只（`code=sh600519,hk00700` 返回“code param error”），所以列表里不画每只的迷你走势，免得每分钟发几十个请求。

A 股涨跌榜来自腾讯的榜单接口 `proxy.finance.qq.com/cgi/cgi-bin/rank/hs/getBoardRankList?_appver=11.17.0&board_code=aStock&sort_type=priceRatio&direct=down&offset=0&count=40`：`sort_type` 是 `priceRatio`（涨跌幅）或 `turnover`（成交额），`direct` 是 `down`（从大到小）或 `up`。返回 JSON，数字都是字符串，`zxj` 现价、`zd` 涨跌额、`zdf` 涨跌幅、`hsl` 换手率、`turnover` 成交额（万元），`code` 带着市场前缀，可以直接当代码用。只在打开榜单页时取，开着时每 30 秒一次。港股、美股的榜单不在这个接口里（猜了几个写法都是 404），东方财富的 `push2` 接口从境外访问返回 502，都没用。涨幅榜常被上市首日（名字前面有 N）和注册制新股前 5 天（有 C）占满，默认不列它们，所以每次取 40 只，筛完再列前 20 只。行业榜是同一个服务的 `rank/pt/getRank?board_type=hy&sort_type=priceRatio&direct=down`，31 个申万一级行业（代码 `pt01801180` 里的 801180 就是申万行业指数的代码），每一行带着领涨股 `lzg`；板块代码不是股票代码，所以行业本身加不进自选，点一下加的是领涨股。新浪的港股、美股涨幅榜（`getHKStockData`、`US_CategoryService.getList`）能取到，但前排多是仙股、权证，暂时不做。

`scripts/check-datasources.sh` 和每周运行的 `datasources` 工作流会打印接口原始返回，接口格式变化时能第一时间发现。手动运行时可以只跑标题匹配某个正则的几项（`ONLY='US|pandata'`），日志短一些。

## 5. 刷新策略

- 默认每 5 秒刷新一次，可选 3、5、10、30、60 秒。
- 按交易所当地时间判断时段：A 股 9:15 集合竞价、9:30–11:30、13:00–15:00；港股 9:00 开市前时段、9:30–12:00、13:00–16:10；美股盘前 4:00、9:30–16:00、盘后至 20:00（美东时间，自动处理夏令时）；期货外汇从纽约时间周日 18:00 到周五 17:00 都算交易中，自选里有它们时工作日全天按设置的间隔刷新，面板上方不写它的状态。
- 自选涉及的所有市场都不在交易时，刷新间隔放宽到 60 秒。
- 不内置节假日日历：如果时间表显示应在交易，但该市场最新行情的日期不是今天，就判定为休市。港股额外留 20 分钟宽限期，抵消行情延时。
- 电脑睡眠时停止轮询，唤醒后立即刷新。打开面板时如果数据超过 3 秒没更新，也会马上刷新。
- 每次刷新带一个递增编号，晚发出的请求结果优先；先发出、后返回的旧结果会被丢弃，避免数据回跳。

## 6. 价格提醒

- 每只证券可以设置 4 个条件：价格高于、价格低于、涨幅达到、跌幅达到。填了持仓（成本大于 0）的还可以设置止盈止损：持仓盈利达到、持仓亏损达到，按相对成本的比例判断，通知里写着现价、成本和持仓盈亏。清掉持仓时这两项一起清掉，改了成本也会清掉当天的提醒记录。点提醒的通知会打开面板并展开那一只，筛选着看不到它时先回到“全部”。发过的提醒（包括收盘小结）记在本机最近的 50 条里（`AlertLog`），通知一闪就过去了，可以从排序菜单的“最近的提醒…”再翻看，点一条同样展开那一只；删掉某只证券时它的记录一起清掉。
- 涨停、跌停提醒（默认关闭）：打开后自选里的 A 股个股（不含指数）现价等于行情里的涨停价或跌停价时提醒，和其他条件一样每个交易日最多一次，所以开板再封板不会重复打扰。它不是每只单独设的条件，由设置里的总开关管，只在本机。
- 52 周新高、新低提醒（默认关闭）：打开后自选里的证券（含指数）当天的最高价达到行情里的 52 周最高、或者最低价达到 52 周最低时提醒，每只每天最多一次。行情里的 52 周最高最低可能已经算上了今天，所以按“达到”判断，不要求超过。它不是前复权的：大比例送转除权那天，价格一下子变低，可能被当成创了新低。
- 异动提醒（默认关闭，可选 1%、2%、3%、5%）：交易时段里每次刷新把每只的现价记一笔，只留最近 5 分钟；现价相对这 5 分钟里的最低点涨了超过阈值算快速拉升，相对最高点跌了超过阈值算快速下跌。同一只同一个方向提醒过以后冷却 15 分钟，免得一路上涨时每次刷新都响。只看常规交易时段，集合竞价和盘前盘后的跳动不算（`RapidMoveDetector`）。
- 同一条件在同一个交易日最多提醒一次，避免价格在阈值附近来回波动时反复打扰。触发记录保存在本地，重启不会重复提醒。
- 修改阈值后会清掉当天的记录，新阈值立即生效。
- 没有成交的证券（停牌、未开盘）不参与判断。

## 7. 持仓与盈亏

- 每只证券可以填持有数量和每股成本价（本币）。指数没有持仓。两项要一起填，数量大于 0，成本价可以是 0（比如送股）。
- 持仓盈亏 = 数量 × 现价 − 数量 × 成本价，比例相对成本；今日盈亏 = 数量 × 今天的涨跌额。休市时显示最近一个交易日的。今天用“记一笔”记过买卖时，今日盈亏把它们算进去：昨天就有、今天没卖的按涨跌额，今天买的按现价减买入价，今天卖的按卖出价减昨收，加起来正好是“现在的市值 − 昨收时的市值 − 今天净投入的钱”，和券商的当日盈亏一个算法。今天全部卖掉的那只不再算持仓，但卖出的那部分还算在当天的今日盈亏里。
- 列表里在代码后面显示持仓盈亏比例（成本为 0 时显示金额），展开后多一行：持有、成本、持仓盈亏、今日盈亏。
- 列表上方的合计卡片按货币分别合计。人民币、港币、美元都有持仓时，再按现在的汇率折成人民币合计一行，汇率来自腾讯的外汇行情 `qt.gtimg.cn/utf8/q=whUSDCNY,whHKDCNY`（第 3 位是现价），10 分钟取一次，只在持仓涉及两种以上货币时才取。成本也按现在的汇率折算，所以折合后的持仓盈亏不含买入以来的汇率变化，鼠标停在“合计”上会说明用的汇率。取不到汇率时只按货币分开显示。
- 合计卡片下面可以展开“持仓分布”：每只一行，横条是它占总市值的比例，按市值从大到小。几种货币都有时按同一个汇率折成人民币再比，没有汇率时先不比；最多单独列 8 只，剩下的合成“其余 N 只”一行；跟着列表上方的筛选走。展开与否记在本机。
- 盈亏记录：每个市场收盘后（和收盘小结同一个判断，`CloseSummary.closedDay`，收盘 16 小时以内）把这个市场的今日盈亏、持仓盈亏和市值记下来，同一天再记就更新，不管开没开收盘小结的通知。每个市场最多留 250 个交易日，存在本机，不同步（几台 Mac 的持仓可能不一样）。合计卡片下面可以展开：每种货币一行，柱子是最近 20 个交易日的今日盈亏，右边是本周（从周一起）、本月记下的加起来。一整天没开机的日子没有记录；筛选着的时候不显示，因为记的是全部持仓。
- 盈亏日历（`ProfitCalendar`）用的就是盈亏记录：一个月一页，周一在前，每天一格，记过的那天写着今日盈亏（菜单栏那种短写法），底色深浅按这个月赚（亏）得最多的那天比；周末、节假日和没开机的日子是空的。几种货币分开看，只能在有记录的月份之间翻。也可以按年看（`ProfitYear`）：十二个月四列三行，每格是那个月记下的今日盈亏加起来，底色按这一年赚（亏）得最多的那个月比，下面写全年合计和赚、亏了几个月；点一格回到按月看那个月。按月还是按年记在本机（`calendar.byYear`），下次打开还是这样。打开“隐藏金额”时格子里不写数，合计也是 `****`。
- 持仓和自选存在一起，也跟着 iCloud 同步。计算在 StoxCore 里，有单元测试。
- 可以选择在菜单栏行情后面显示今日盈亏，比如“今日 +¥688 -HK$120”，每种货币一段；有汇率时折成人民币只显示一个数，更省地方。也可以改成显示持仓盈亏（“持仓 +¥1.29万”，隐藏金额时是相对成本的比例）。不参与轮流显示，默认关闭，右键隐藏行情时一起隐藏。
- 编辑持仓时可以按成交“记一笔”：买入时数量相加、成本价按加权平均重新算（价格不填按现价），卖出只减数量、成本价不变（移动平均法），全部卖出就清掉持仓。算出来的结果先填回输入框，点保存才生效。
- 走势图上的成本线和买卖点（默认打开，设置里可以关）：分时图和 K 线上，成本价落在图的纵轴范围里时画一条青色虚线，不为了它扩大范围，免得价格线被压扁；K 线是前复权的，除权以后成本线和早先的 K 线不完全可比。记下的买卖按交易日落到 K 线上：日 K 按日期，周 K、月 K 按同一周、同一个月（K 线的日期是那一周、那个月的最后一个交易日），买入在那一根下面标 B，卖出在上面标 S，同一根上都有就都标。
- 走势图上的提醒线（默认打开，设置里单独可以关）：设了价格提醒的，分时图和 K 线上在提醒价画一条褐色的短虚线（`ChartLevel`，颜色和涨跌的红绿、均线的橙蓝紫、成本线的青色都分得开）。止盈止损按成本价折成价格：成本价 ×（1 ± 比例），和提醒时的算法一样（持仓盈亏比例相对成本），所以价格越过这条线就会提醒；涨跌幅提醒按昨收折成价格，只画在分时图上，K 线上的是过去的日子。和成本线一样只画落在纵轴范围里的，不扩大范围。线旁边的字（`LevelLabelLayout`）写在线的上面，贴着顶边时写在下面；几条线挨得近、字上下叠在一起时横着排成一排，分时图上放在中间（四个角写着最高最低），K 线上靠右。
- 分红送转也在编辑页记：A 股按公告的说法填“每 10 股派多少、送转多少”，港股、美股填每股派多少（没有送转）。现金分红从总成本里扣掉，送转的股加到数量里，成本价 = (原来的总成本 − 到手的现金) ÷ 新的股数，不低于 0；到手的现金算已实现盈亏。除权除息那天行情里的昨收已经按除权调过，所以今日盈亏不用另外处理。
- 记下的每一笔也留在这只的买卖记录里（`Trade`，每只最多 100 笔），跟着自选一起同步和备份，持仓清掉以后也还在。卖出时按卖出前的成本价算出已实现盈亏：(卖出价 − 成本价) × 数量。每一笔算在哪个交易日：这个市场今天已经开始交易（含盘前、盘后）时是今天，否则是最新行情所在的交易日，所以第二天开盘前补记的算前一天。编辑页列出最近 3 笔（编辑页不滚动，小屏幕放不下更多）和今年卖出、分红一共赚了多少，可以删掉记错的一条（只删记录，不改持仓）；合计卡片下面按币种写今年已实现的盈亏，跟着列表上方的筛选走。
- 收盘小结（默认关闭）：有持仓的市场收盘后（美股是进入盘后时）发一条通知，写着今日盈亏、持仓盈亏和市值；这个市场有两只以上持仓时，再写上今天涨得最多、跌得最多的是哪只。按最近一个交易日记住发过没有，收盘 16 小时以内打开 Mac 也会补发一次，第二天开盘前就不再发前一天的；节假日最新行情是好几天前的，不会误发。这个开关不同步，免得几台 Mac 各发一遍。
- 每只还可以写一句备注，展开后在详情里显示，鼠标停在列表里的小图标上也能看到，跟着 iCloud 同步。
- 隐藏金额（默认关闭，合计卡片“市值”旁边的小眼睛或设置里切换，记在本机、不同步）：给别人看屏幕时用。面板里的市值、盈亏金额、本周本月、已实现和持有数量换成 `****`，盈亏比例、持仓分布的比例和盈亏记录的柱子照常显示（只看得出相对大小）；菜单栏的今日盈亏换成相对昨日市值的比例（`PortfolioSummary.dayProfitPercent`，有汇率时是折合后的）；收盘小结只写今日、持仓的盈亏比例和涨跌最多的两只，止盈止损的通知只写持仓盈亏比例。最近的提醒里记的是发出时的文字，打开隐藏以前发的还带着金额。编辑页照常显示实际数字（要填要改），复制出来的持仓表格、买卖记录和盈亏记录也是实际数字。

## 8. 菜单栏空间

带刘海的 MacBook 菜单栏很挤，放不下的图标会被系统直接隐藏，所以：

- 默认只把上证指数显示为“上证 3825.65 -1.61%”（英文界面是标普 500：“S&P 500 7651.54 -0.25%”），其余股票在面板里看。
- 名称、价格、涨跌幅三项可以分别关闭，例如只显示“-1.61%”。
- 每只股票可以设置菜单栏简称；没有设置时按宽度自动截断，中文最多 4 个字。
- 固定多只时可以开启轮播，每 5 秒切换一只。
- 可以排成上下两行（`TickerLayout.stacked`，和名称、价格、涨跌幅的开关一起同步）：每只左边一行名称（12 号字），右边上下两行 9.5 号等宽数字，价格在上、涨跌幅在下，右对齐；菜单栏上的盈亏也是金额在上、比例在下（隐藏金额时只有比例）。右边只剩一个数时它单独一行、上下居中。两行加起来要放进 22 点高的菜单栏，行距取 10 点，上一行数字下面的空白和下一行重叠，数字本身不碰。这些画成一张图（`StackedTickerImage`，用绘制闭包，菜单栏换深浅色时重新画，颜色跟着变），读屏读的是连成一行的文字。同样三只，宽度大约是一行排法的一半多一点。
- 数字使用等宽字形，价格跳动时菜单栏宽度不抖。
- 右键单击菜单栏图标一键隐藏行情，只留图标；再右键一次恢复。

另外可以选“休市时只显示图标”：菜单栏上的证券（以及显示今日盈亏时有持仓的市场）所在的市场都休市时只剩图标，任何一个进入盘前或开盘就恢复，晚上不占菜单栏的地方。

## 9. 涨跌颜色

三种：红涨绿跌（默认，A 股和港股的习惯）、绿涨红跌（美股的习惯）、不显示红绿。选“不显示红绿”时：

- 菜单栏的价格和涨跌幅用菜单栏默认的文字颜色，跟随深浅色模式。
- 面板里的价格用默认文字颜色，涨跌幅色块换成淡淡的中性底色，靠正负号区分涨跌。
- 市场标签（沪、深、港、美）和交易状态圆点也不再用彩色，状态只用明暗区分交易中和休市。

## 10. iCloud 同步

同步的内容是自选列表（顺序、菜单栏固定、简称、备注、分组、持仓、价格提醒）和一部分设置：刷新间隔、休市降频、涨跌颜色、菜单栏显示哪几项、轮播、提醒开关。“只显示图标”、快捷键、登录时启动、自动检查更新只和这台 Mac 有关，不同步。

| 方案 | 结论 |
|---|---|
| iCloud 云盘里的一个文件（采用） | 不需要开发者证书和 entitlement，临时签名的 App 也能用；用户在访达里看得到这个文件 |
| CloudKit / `NSUbiquitousKeyValueStore` | 需要 Apple 开发者账号签名并申请 iCloud entitlement，临时签名的发布包用不了 |

- 文件是 `~/Library/Mobile Documents/com~apple~CloudDocs/Stox/sync.json`，记录格式版本、写入时间、是哪台 Mac 写的，以及内容。读写经 `NSFileCoordinator` 协调；还没下载到本机的文件先请求下载。
- 本机的自选或设置改动后等 1 秒（连续改动合并成一次）写上去；退出时还有没写上去的改动，会先写完再退出（kill 这类信号也一样）。监听同步文件夹的变化，另外每 30 秒、打开面板时、电脑唤醒后也检查一次；文件的修改时间和大小没变就不读。
- 判断按内容而不是时间：云端内容和本机不同、也不是上次同步过的那份，才应用到本机；本机内容和上次同步的不同，才写上去。应用云端内容时不会再把它当作本机改动写回去。
- 上次同步过的内容保存在本机，重新启动后仍然分得清是谁改的：iCloud 没变而本机变了，就把本机的写上去，而不是用 iCloud 里的旧内容覆盖。
- 两台 Mac 同时改动时 iCloud 会留下冲突版本：比较所有版本的写入时间，晚的胜出，写回去并清掉其他版本。
- 第一次开启时 iCloud 里已经有自选，就问用户：用 iCloud 的、用本机的，或者合并（以 iCloud 的顺序和每只的设置为准，本机独有的追加在后面）。
- 读不懂的条目跳过而不是整份失败；更新版本的 Stox 写的新格式读不懂时报错，而不是用本机数据覆盖它。
- App Store 版在沙盒里，读不到 iCloud 云盘里的其他文件夹，改用 App 自己的 iCloud 容器 `iCloud.io.github.whrss9527.stox`（`容器/Documents/sync.json`，格式不变）。位置由 `SyncLocation.resolve` 决定：`STOX_SYNC_DIR` > 签名里有容器的 entitlement 时的容器 > iCloud 云盘/Stox。有没有 entitlement 用 `SecTaskCopyValueForEntitlement` 看，没有时不碰容器的接口，GitHub 版的行为不变；容器地址在后台线程上用 `FileManager.url(forUbiquityContainerIdentifier:)` 要（第一次可能要几秒），要到之前同步先等着。两个版本之间不互通，详见 [app-store.md](app-store.md)。

### 备份到文件

设置的 iCloud 同步页里可以把自选和会同步的设置导出成一个 JSON 文件（默认叫“Stox 自选 2026-09-28.json”），格式就是 iCloud 里的同步文件（`SyncDocument`），带着是哪台 Mac、什么时候导出的。导入时读出来先问：替换本机的自选和设置，或者只添加本机没有的证券（本机的自选、顺序和设置都不动，`SyncContent.importing`）。导入和在本机改动走同一条路，开着同步时会同步上去。更新版本写的新格式读不懂时报错，不会半读半写。

## 11. 检查更新与一键更新

- 启动 5 秒后和之后每 6 小时请求一次 GitHub 的 `releases/latest`，忽略草稿和预发布。版本号逐段按数字比较。有新版本时发一条通知（同一个版本只通知一次），面板底部出现更新条；可以跳过某个版本。
- 一键更新的步骤：下载 `Stox.zip`（显示进度，可以取消）→ 校验 SHA-256（优先用 GitHub 给附件算的摘要，没有时用发布附带的 `SHA256SUMS.txt`）→ 用 `ditto` 解压并去掉隔离标记 → 确认 bundle identifier、版本号对得上，`codesign --verify --deep --strict` 通过；当前版本是开发者证书签名时，新版本也必须是同一个 Team ID 签的 → 替换 → 起一个独立的小进程等当前进程退出后打开新版本。
- 替换时先把新程序挪到同一个文件夹里的隐藏名字，旧的挪开，再改名，失败就换回去。文件夹没有写权限（标准账户装在“应用程序”里）时用系统的授权对话框以管理员身份做同样的事；被 macOS 的“App 管理”保护拦住时提示去系统设置里允许。
- 从“下载”文件夹直接打开的 App 会被系统搬到只读的临时位置运行（App Translocation）。这时更新装进“应用程序”（没有写权限时装进 `~/Applications`），旧的那份移到废纸篓，从新位置重新打开。
- 自选和设置在 UserDefaults 里，和程序文件无关，更新后都保留。

### App Store 版

App Store 版编译时加 `-D APP_STORE`（`STOX_FLAVOR=appstore scripts/build-app.sh`，用单独的编译目录 `.build/appstore`）：`Updater`、`UpdateInstaller`、更新条、“检查更新”菜单、“自动检查更新”开关、`Shell` 都不编译进去，“已更新到 x.y.z”的卡片也不显示（不去 GitHub 取更新内容），更新交给 App Store（审核指南 2.4.5）。其他功能相同，沙盒里的 entitlement 只有联网、用户选择的文件（备份到文件）和 iCloud。上架步骤见 [app-store.md](app-store.md)。

## 12. 发布说明

`CHANGELOG.md` 按版本写这次改了什么。发布时 `scripts/release-notes.sh` 把对应的一节放在 GitHub 发布说明的最前面（“更新内容”），后面才是安装步骤和自动生成的改动列表。更新以后面板上方的“已更新到 x.y.z”会按版本号取这个版本的发布说明，列出“更新内容”的前几条；隔了几个版本才更新时（启动时记下上一次运行的版本，提示没关又更新了就从更早的算起），改取最近 30 个发布（`releases?per_page=30`），每个版本一行它第一条的开头一句（到第一个冒号，写在冒号前的一般是功能名；没有冒号就到第一个逗号或句号，最长 36 个字），最多 5 个版本，更早的合成一行“还有几个”。“关于与更新”里发现新版本时同样取这个列表，列出从现在的版本到新版本之间每个版本的“更新内容”（最多 6 个），在后台取，不耽误检查和一键更新。App 的“关于与更新”页也只显示“更新内容”这一节，旧版本的发布说明没有这一节时，去掉安装步骤和自动生成的部分再显示。

## 13. 界面语言

界面有简体中文和英文两种，默认跟随系统语言：系统语言是中文时是中文，其他语言都是英文（`CFBundleDevelopmentRegion` 是 `en`）。

- **设置里选语言**。设置的“通用”页有“界面语言”：跟随系统、English、简体中文（语言名用它自己的写法）。选了某种语言就把 `AppleLanguages` 写进 Stox 自己的偏好设置，跟随系统时删掉这个键；这和“系统设置 → 通用 → 语言与地区 → App”里单独给 Stox 选语言是同一个键，两边看到的一样（在那里选了 Stox 没有的语言，设置里显示为跟随系统）。系统启动时按它选翻译表，`AppLanguage.isEnglish` 也只在启动时算一次，所以要重新启动：选的和这次启动时的不一样时，下面写着“重新启动 Stox 后生效”和“立即重新启动”按钮。重新启动用 `NSWorkspace.openApplication`（`createsNewApplicationInstance`）打开一个新实例，参数里带 `--relaunch-after <旧进程号>`，打开后旧的退出；新实例在 `main` 里先等旧的退出（最多 15 秒）再建菜单栏图标、注册快捷键。不用一键更新的 shell 脚本，所以 App Store 版（沙盒，没有 `Shell`）一样能用。这个设置只在这台 Mac 上，不同步也不写进备份。

- **中文原文就是键**。代码里显示给用户的文字都写成 `L("中文原文", 参数…)`（`StoxCore/AppLanguage.swift`），原文同时是 `Resources/en.lproj`、`Resources/zh-Hans.lproj` 里 `Localizable.strings` 的键，打包时复制进 `Stox.app/Contents/Resources`。命令行工具和单元测试里没有翻译表，`L` 原样返回中文，测试照旧比较中文。
- **不用 SwiftUI 自己的查表**。Stox 是 SwiftPM 的可执行文件，`Text("…")` 的插值会生成 `%lld`、`%@` 这样依赖参数类型的键，脚本很难检查全，所以一律写成 `Text(L("…"))`：`L` 返回的是字符串，SwiftUI 原样显示。带参数的文字用 `%@` 占位，参数按字符串插值的写法转成文字，数字的格式和原来一样；英文语序不同时译文里用 `%1$@`、`%2$@`。
- **检查**。`scripts/check-localization.py` 检查两种语言的键完全一致、代码里用到的键都有翻译、占位数量对得上，并且代码里没有漏掉 `L()` 的中文（日志、诊断输出和行尾标了 `// l10n-ignore` 的数据除外，比如默认自选的名称和发布说明的标题）。CI 的 Linux 任务每次都跑。
- **数字**。英文界面里大数用 K、M、B、T（`27.83亿` 是 `2.78B`），成交量是 lots、shares；小数位数、正负号和百分比不变。日期、相对时间和月份名跟着界面语言。
- **证券名称**（`EnglishName`）。行情接口给的名称都是中文（AAPL 是“苹果”），英文界面里有英文来源的换成英文：指数用内置的表（SSE Composite、Hang Seng、S&P 500，菜单栏上是 SSE、HSI 这样的简称），期货外汇和环球股指用品种表里的英文名（Spot Gold、WTI Crude、EUR/USD、Nikkei 225）；美股用腾讯行情第 46 位的英文公司名，去掉 Inc.、Corporation、Ltd 这类字样（`Apple Inc.` 是 Apple），菜单栏上用代码（AAPL），ETF 的英文名是基金全称、太长，用代码；港股用第 46 位的英文简称（TENCENT，新浪是第 0 位），菜单栏上整个词地取前 12 个字以内；没有英文名的（还没取到行情、新浪的美股）用代码。A 股和场外基金没有英文来源，照旧是中文。英文名只在显示时换，记下的名称还是数据源的中文名，所以中英文两台 Mac 同步时名称不会来回改；用户设的菜单栏简称总是优先。中文界面不变。英文界面里搜索也按英文名找表里的指数（S&P 500、Dow、Hang Seng，腾讯的搜索接口不一定找得到）。
- **默认自选**。没有保存过的自选时按界面语言选：中文是三地的主要指数加茅台、腾讯、苹果，菜单栏上是上证；英文是美股三大指数、苹果、微软、英伟达、伦敦金和欧元美元，菜单栏上是标普 500（简称 S&P 500）。“添加常用指数”加的也按界面语言。已经有自选的不动。
- **不翻译的**：A 股和场外基金的名称、更新日志和发布说明只有中文，命令行工具 `stox-cli` 是给开发者用的，也只有中文。
- CI 的系统语言是英文：启动测试先用 `AppleLanguages` 把 Stox 固定成中文（README 的截图和检查菜单栏文字都用中文界面），最后带上 `-AppleLanguages '(en)'` 再启动几次，检查界面是英文，截图是 `shots/en-*`；其中设置的“通用”页不带参数、只在偏好设置里写 `AppleLanguages` 为 `en`，检查设置里选 English 的效果。App Store 版在沙盒容器的偏好设置里写 `zh-Hans`，检查沙盒里也按它显示。

## 14. 质量保障

- **StoxCore 单元测试**：用 2026-09 抓取的真实接口返回做样本，覆盖代码解析、三地行情字段、搜索、交易时段、节假日判断、提醒去重、格式化和持久化，以及持仓盈亏和按币种合计、批量粘贴代码的解析、K 线解析和用实时行情更新最后一根，同步文件的读写、合并和拉推规则、GitHub 发布信息解析、版本比较、校验文件解析和安装位置判断。StoxCore 不依赖 AppKit，在 Linux 上也能跑。
- **实时数据冒烟测试**：CI 用 `stox-cli` 请求真实接口，确认解析结果合理。
- **macOS 构建**：CI 在 macOS 上编译 Apple 芯片 + Intel 通用版，组装、签名 `Stox.app`。
- **行情源切换测试**：用 `STOX_QUOTE_ENDPOINT` 把腾讯的行情地址指向一个连不上的端口，确认自动改用新浪、列表照常有行情。
- **启动测试**：CI 启动打包好的 App，分别打开自选列表、展开详情（分时、A 股日 K、美股月 K）、搜索结果、设置窗口的各页，以及右键切换后的“只显示图标”，并用 `--keys` 模拟方向键和回车，检查选中和展开的是不是预期的那一只；进程中途退出就判定失败，同时记录内存占用。每个页面都会截图并作为构建产物上传；提交信息带 `[screenshots]` 时，截图还会以检查注释的形式发布，可以通过 GitHub API 取回。
- **iCloud 同步测试**：用 `STOX_SYNC_DIR` 指向一个假的 iCloud 云盘文件夹，里面放好“另一台 Mac”写的文件。确认启动时拉取并应用（包括“不显示红绿”），运行中文件被替换后几秒内收到改动，文件被删后把本机的写回去；再模拟本机改完没来得及写上去就退出，确认下次启动时写上去而不是被覆盖。
- **App Store 版测试**：另一个任务用 ad-hoc 签名打一个带沙盒的 App Store 版（`ADHOC=1 scripts/build-app-store.sh`，去掉要描述文件的 iCloud entitlement），确认程序里没有更新相关的类型，启动后在沙盒里运行、取得到行情、面板和设置窗口打得开、同步文件写得进容器，并做 1440×900 的 App Store 截图。
- **一键更新测试**：用打包好的程序造一个 9.9.9 版本，放在本地 HTTP 服务器上当作最新发布（`STOX_UPDATE_URL`）。确认发现新版本，原地下载、校验、替换并以 9.9.9 重新启动；再模拟从临时位置运行，确认装进“应用程序”、旧的移到废纸篓、新程序没有隔离标记。
- **数据源巡检**：`datasources` 工作流每周打印一次接口原始返回。

## 15. 已知限制与后续方向

- 没有 Apple 开发者证书，发布包是临时签名，首次打开需要手动放行（之后的一键更新会去掉隔离标记，不用再放行）。有证书后设置 `CODESIGN_IDENTITY` 即可正式签名，再接入公证；到时 iCloud 同步也可以换成 CloudKit。
- 港股为延时行情；需要实时港股时，可以新增一个实现 `QuoteProvider` 的数据源。
- 盈亏记录只记这台 Mac 开着的交易日（收盘 16 小时以内打开过就算），一整天没开机的日子是空的；持仓是手填的，记下的盈亏跟着持仓走，不是券商的对账单。
- 美股分时没有成交额，均价线是按每分钟成交量加权的近似。
- 外汇没有分时图和迷你分时，新浪的外汇分时接口从境外太慢，可以试着只取开盘以来的那几百条。
- 可以继续做的功能：用盈亏记录画收益曲线。
